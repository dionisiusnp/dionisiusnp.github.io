Rekomendasi Mekanik

Pilihan Game Mechanics di Greenfoot

Berikut empat mekanik permainan yang bisa diimplementasikan di Greenfoot sesuai konsep Cocothink. Pilihan utama ditandai khusus — paling sesuai dengan alur dungeon + quiz yang dirancang.

⭐ Pilihan Utama 🏰

Top-Down Dungeon Explorer

Karakter bergerak 4 arah (WASD / arrow key) di peta dungeon 2D. Setiap zona/pintu yang dimasuki memicu quiz overlay berisi soal pilihan ganda. Jawaban salah mengurangi heart; jawaban benar memberikan EXP dan membuka jalur ke quest berikutnya. Sangat natural dengan konsep "arena → tantangan → lanjut".

Arrow Key Movement Collision Detection QuizOverlay Actor Room Transition HUD (Heart, EXP)
💡 Paling mudah dibangun di Greenfoot — World + Actor sudah mendukung movement dan collision secara native.
✅ Possible ⚔️

Turn-Based Battle vs Bug Monster

Setiap quest memunculkan "musuh" berupa Bug atau Error Monster. Pemain memilih jawaban yang berfungsi sebagai serangan. Jawaban benar = damage ke musuh; jawaban salah = musuh menyerang balik (heart berkurang). Musuh dikalahkan → EXP diperoleh → lanjut ke quest berikutnya.

Turn System Health Bar Actor Enemy AI (static) Battle Animation Damage Feedback
💡 Cocok digabung dengan mekanik utama — dungeon explorer lalu battle saat boss room.
✅ Possible 🏃

Side-Scrolling Checkpoint Runner

Karakter berlari otomatis ke kanan. Saat menabrak papan pertanyaan atau NPC, permainan berhenti dan quiz muncul. Jawaban benar membuka rintangan; jawaban salah memunculkan hambatan. Cocok untuk segmentasi materi yang linear dan berurutan.

Auto-Runner Obstacle Actor Trigger Zone Scrolling World Checkpoint Flag
💡 Alternatif untuk materi yang harus diselesaikan urut (misal: setup → route → controller).
🎁 Bonus 🧩

Grid Maze Explorer

Peta berbasis grid (tile map). Karakter berpindah tile per tile. Setiap persimpangan atau portal mewakili satu quest. Greenfoot sangat mendukung grid-based world karena ukuran cell dapat dikonfigurasi langsung di constructor World. Cocok untuk pemula karena movement-nya sederhana.

Grid World Tile Movement Path Unlock Portal Actor Fog of War
💡 Sangat mudah diimplementasikan karena Greenfoot dirancang khusus untuk grid world.

Alur Permainan

Tahap Demi Tahap — Dari Login ke Selesai

Berikut alur lengkap yang dialami pemain sejak membuka game hingga menyelesaikan seluruh dungeon. Setiap tahap dirancang berurutan dan saling terhubung.

🚀
Tahap 1 — Masuk Platform

Login & Verifikasi Akun via Laravel

Pemain membuka platform Cocothink di browser (Laravel web app). Login menggunakan akun yang sudah terdaftar. Setelah autentikasi berhasil, sistem memuat data progres pemain dari database — dungeon mana yang sudah selesai, total EXP, level, dan jumlah heart tersisa.

PlatformLaravel web app (browser)
Data dimuatProgres, EXP, Level, Heart
Jika baruHeart = 3, EXP = 0, Level = 1
🏠
Tahap 2 — Lobby & Pilih Dungeon

Layar Peta Dungeon — Pilih Arena

Setelah login, pemain masuk ke layar peta dunia. Ditampilkan 7 dungeon dalam urutan linear. Dungeon yang sudah diselesaikan ditandai dengan ikon gembok terbuka dan lencana bintang. Dungeon yang belum dibuka terlihat terkunci (gembok tertutup, abu-abu).

TampilanPeta 2D dengan 7 titik dungeon
TerkunciAbu-abu, tidak bisa diklik
TersediaBerwarna, ada tombol "Masuk"
SelesaiTanda ✓ + bintang perolehan
🗺️
Tahap 3 — Masuk Dungeon

Game Greenfoot Dimuat — Pemain di Dalam Dungeon

Saat pemain menekan "Masuk Dungeon", game Greenfoot diluncurkan (embed di halaman Laravel atau dibuka terpisah). Pemain melihat karakter mereka di pintu masuk dungeon. Layout dungeon sesuai segmentasi topik — misal Dungeon 3 bertema "ruang server" untuk materi migrasi database.

EngineGreenfoot (Java/embed)
World size±800×600 px, tile 32px
HUD aktifHeart ❤️ · EXP bar · Nama dungeon
KarakterMuncul di spawn point
🧭
Tahap 4 — Eksplorasi & Navigasi

Pemain Menggerakkan Karakter Menuju Quest Zone

Pemain menggunakan ↑ ↓ ← → atau W A S D untuk menggerakkan karakter. Di dalam dungeon terdapat beberapa Quest Zone yang ditandai secara visual (tanda tanya berkilau, portal glowing, atau NPC). Pemain harus mendatangi setiap zone secara berurutan.

KontrolArrow key atau WASD
Quest ZoneVisual: ikon ❓ beranimasi
UrutanZone 1 → 2 → 3 → Boss (opsional)
Zone terkunciTidak bisa diakses sebelum zone sebelumnya selesai
❓
Tahap 5 — Trigger Quest & Quiz Muncul

Overlay Quiz Tampil — Pilih Jawaban

Saat karakter menyentuh Quest Zone, game pause sejenak dan quiz overlay muncul di atas layar Greenfoot. Ditampilkan pertanyaan beserta 4 opsi jawaban (A, B, C, D). Timer opsional berjalan (misal 30 detik). Pemain memilih jawaban dengan menekan tombol atau mengklik.

Format soalPilihan ganda 4 opsi (A–D)
Contoh soal"Perintah artisan untuk membuat migration adalah..."
Opsi jawabanA. make:model   B. make:migration   C. make:controller   D. migrate
Timer30 detik (opsional, dikonfigurasi)
💔
Tahap 6a — Jawaban Salah

Heart Berkurang — Feedback Kesalahan Tampil

Jika pemain memilih jawaban yang salah: efek visual merah muncul (screen shake atau flash), satu heart berkurang dari HUD, dan pesan singkat ditampilkan yang menjelaskan jawaban yang benar beserta alasannya. Quest zone tetap aktif — pemain bisa mencoba lagi setelah feedlback ditutup.

EfekScreen flash merah + suara "buzz"
HeartBerkurang 1 (dari 3 → 2 → 1 → Game Over)
FeedbackJawaban benar + penjelasan singkat
Game OverHeart = 0 → kembali ke lobby, heart reset
✅
Tahap 6b — Jawaban Benar

EXP Bertambah — Quest Zone Selesai

Jika jawaban benar: efek visual hijau muncul (partikel bintang, layar glow), EXP bertambah sesuai kesulitan soal, dan animasi "Quest Complete" tampil sebentar. Quest Zone berubah tampilan (tanda centang, warna berubah, ikon terkunci hilang) dan pemain bisa melanjutkan eksplorasi menuju quest berikutnya.

EfekPartikel ⭐ + suara "ding"
EXP+10 EXP (normal), +15 EXP (bonus: jawab cepat)
Zone statusBerubah jadi ikon ✓ (selesai)
ProgresTersimpan otomatis ke Laravel backend
🚪
Tahap 7 — Pindah Quest / Dungeon

Lanjut ke Quest Berikutnya atau Dungeon Selanjutnya

Setelah semua quest zone dalam satu dungeon selesai, pintu keluar dungeon terbuka. Pemain mendatangi pintu dan memilih: lanjut ke dungeon berikutnya atau kembali ke peta dunia. Jika dungeon memiliki Boss Quest (dungeon terakhir tiap segmen), Boss akan muncul sebelum pintu keluar terbuka.

Kondisi lanjutSemua quest zone selesai
Boss QuestSoal gabungan dari seluruh quest dungeon (D7 saja)
Dungeon clearBadge + bonus EXP "Dungeon Complete"
Akses bukaDungeon berikutnya terbuka di peta

Tahap 8 — Penyelesaian & Pencapaian

Semua Dungeon Selesai — Profil & Sertifikat

Setelah semua 7 dungeon diselesaikan, pemain mendapatkan layar "Cocothink Complete" dengan ringkasan: total EXP, level akhir, jumlah jawaban benar/salah, dan badge koleksi. Data sinkron ke Laravel — profil pemain diperbarui, dan sertifikat digital dapat diunduh dari platform.

RingkasanEXP total · Level · Akurasi jawaban
BadgeKoleksi badge per dungeon + badge "Cocothink Master"
SertifikatPDF digital dari platform Laravel
LeaderboardSkor dibandingkan dengan pemain lain
Sistem Reward

Heart, EXP & Level — Mekanisme Penghargaan

Tiga elemen utama gamifikasi yang mengatur dinamika permainan dan motivasi belajar pemain.

❤️

Heart (Nyawa)

Mengatur konsekuensi dari jawaban salah. Mendorong pemain untuk berpikir sebelum menjawab.

🔴Awal sesi: 3 heart
💔Jawab salah: -1 heart + feedback jawaban benar
💀Heart = 0: Game Over — kembali ke lobby, heart reset
❤️Heart tidak bisa bertambah dalam satu sesi dungeon
🔄Heart reset setiap kali mulai dungeon baru
⭐

EXP (Pengalaman)

Mengukur progres belajar. Terakumulasi dari seluruh dungeon dan tersimpan permanen di profil.

✅Jawab benar: +10 EXP
⚡Jawab benar dalam 10 detik: +15 EXP (bonus speed)
🏰Dungeon Clear: +20 EXP bonus tambahan
🏆Boss Quest benar: +25 EXP
❌Jawab salah: 0 EXP (tidak dikurangi)
🏅

Level & Badge

Representasi visual pencapaian pemain. Memberi rasa progres yang terlihat jelas.

1️⃣Lv.1 Novice — 0–99 EXP (mulai)
2️⃣Lv.2 Apprentice — 100–249 EXP
3️⃣Lv.3 Developer — 250–449 EXP
4️⃣Lv.4 Engineer — 450+ EXP
🏆Badge per dungeon — diperoleh setelah dungeon clear
Implementasi Teknis

Greenfoot — Komponen & Struktur Kode

Gambaran teknis bagaimana game dibangun di Greenfoot menggunakan hierarki World dan Actor. Ini adalah panduan referensi bagi tim yang mengerjakan bagian game engine.

🌍

DungeonWorld

extends World

World utama game. Setiap dungeon adalah satu subclass DungeonWorld. Berisi semua Actor dan logika spawn karakter, quest zone, dan HUD.

public class Dungeon3World extends DungeonWorld { Dungeon3World() { super(800, 600, 1); addObject(new PlayerActor(), 60, 300); addObject(new QuestZone("Q1"), 200, 200); } }
🧑

PlayerActor

extends Actor

Karakter pemain. Menangani input keyboard (WASD/arrow), animasi sprite, dan deteksi collision dengan QuestZone dan dinding.

public class PlayerActor extends Actor { public void act() { handleMovement(); QuestZone z = (QuestZone) getOneIntersectingObject(QuestZone.class); if (z != null) z.trigger(); } }
❓

QuestZone

extends Actor

Area trigger di dungeon. Saat PlayerActor menyentuhnya, game pause dan QuizOverlay ditampilkan. Menyimpan ID soal yang akan diambil dari bank soal.

public class QuestZone extends Actor { private String questId; boolean completed = false; public void trigger() { if (!completed) { // tampilkan quiz overlay (DungeonWorld)getWorld() .showQuiz(questId); } } }
📋

QuizOverlay

extends Actor

Overlay yang menampilkan pertanyaan dan 4 tombol jawaban. Render teks langsung di Greenfoot menggunakan GreenfootImage. Mengirim hasil ke HUDManager.

public class QuizOverlay extends Actor { void drawQuestion(String q, String[] opts) { GreenfootImage img = new GreenfootImage(600,300); img.setColor(Color.BLACK); img.fill(); img.drawString(q, 20, 40); // render opsi A–D... setImage(img); } }
💗

HUDManager

extends Actor

Mengelola dan merender HUD di sudut layar: ikon heart, EXP bar, nama dungeon, dan nama pemain. Update otomatis setiap act() cycle.

public class HUDManager extends Actor { int hearts = 3; int exp = 0; void onWrong() { hearts--; if (hearts <= 0) triggerGameOver(); else redrawHUD(); } void onCorrect(int expGain) { exp += expGain; redrawHUD(); } }
💾

ProgressSync

HTTP → Laravel API

Komponen yang mengirim data progres dari Greenfoot ke backend Laravel via HTTP request setelah setiap quest selesai atau dungeon clear. Disimpan ke database pemain.

// Dipanggil setelah quest selesai void syncToLaravel(String userId, String questId, int expEarned) { // POST ke API Laravel: // /api/progress/update // { user_id, quest_id, exp } URL url = new URL(API_BASE + "/api/progress/update"); // ... HttpURLConnection request }
